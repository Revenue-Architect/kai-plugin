How to run it

5Qualify — Run the question bank before booking anything. Choose Blueprint/advisory or scoped implementation. Fail Fit or Authority → decline or refer. Owner: CEO

1Blueprint/advisory / Implementation scoping / Referral discovery — Each path must produce the same Baseline artifacts. Owner: CEO + CTO

5Proposal + SOW — Assembled straight from the Baseline. Cap explicit, net investment shown. Owner: CEO

2API-First Migration — Dry Run before live; reconcile within tolerance; legacy POS stays live until proven (Parallel Validation). Owner: CTO

3Launch QA — Run once per location. No Critical open at go-live; signed off by a named person. Owner: CTO + CEO

4Ops Care — Monthly health report is the backbone. Expansion only on green/yellow accounts; loops back to Proposal. Owner: CEO + CTO

★ The Engagement Baseline is the source of truth. Entity scope, data cap, migration lane, risk register, recommendation matrix, and retainer fit. Every later pack inherits from it. Blueprint/advisory, implementation scoping, and Shopify referral discovery can each produce it, but every path must converge here before any build starts. A weak Baseline turns every downstream stage back into custom work.

Two non-negotiables

  • Never skip the Baseline artifacts. They are what make the system repeatable instead of bespoke.
  • Treat the gate (◆) as a hard stop. No proposal without a Baseline; no cutover without a passed Dry Run; no location live on optimism. This protects the Parallel Validation guarantee and the case-study-quality bar.
